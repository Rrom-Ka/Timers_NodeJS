# Веб-приложение для трекинга времени (Timers App)

Простое и эффективное веб-приложение для управления таймерами в реальном времени. Позволяет пользователям регистрироваться, авторизовываться, создавать текстовые описания для задач, запускать таймеры и останавливать их.

Особенность архитектуры заключается в **синхронизации состояния интерфейса через WebSocket**: каждую секунду сервер автоматически обновляет прогресс тикающих таймеров у всех подключенных клиентов, исключая необходимость постоянных AJAX-запросов с фронтенда.

## 🚀 Основные возможности

- **Полноценная авторизация:** Регистрация и вход пользователей с сессиями на базе кук (`httpOnly`).
- **Безопасное хранение:** Пароли хешируются с использованием алгоритма `SHA-256` и уникальной криптографической соли на бэкенде.
- **Обновления в реальном времени (Real-time UI):** Прогресс активных таймеров обновляется каждую секунду через WebSocket-соединение.
- **REST API + WS:** Создание и остановка таймеров происходят через легковесные HTTP POST запросы, а актуальные списки возвращаются через сокеты.
- **Отказоустойчивость бэкенда:** Асинхронные цепочки и запросы к базе данных защищены блоками `try/catch` и оптимизированы под рекурсивный `setTimeout` для предотвращения перегрузки пула соединений MongoDB.
- **Современный UI:** Адаптивный и лаконичный интерфейс на базе фреймворка **UIkit 3**.

## 🛠 Стек технологий

**Бэкенд:**

- Node.js (Платформа)
- Express.js (Веб-фреймворк)
- MongoDB Драйвер v3.6 (База данных)
- ws (WebSocket-сервер)
- Nunjucks (Шаблонизатор на сервере)
- Cookie-parser & Body-parser (Middleware)

**Фронтенд:**

- Vue.js v2 (Реактивный JS-фреймворк для управления состоянием)
- UIkit v3.5.4 (CSS/JS фреймворк для верстки и уведомлений)

## 📋 Системные требования

- **Node.js**: Версия `>= 12.0.0`
- **MongoDB**: Версия `v3.6+` или облачный кластер (MongoDB Atlas)

## 🔧 Установка и запуск проекта

### 1. Клонирование репозитория

```bash
git clone https://github.com
cd имя-репозитория
```

### 2. Установка зависимостей

Установите все необходимые npm-пакеты (включая dev-зависимости для линтинга и форматирования):

```bash
npm install
```

### 3. Настройка переменных окружения

Создайте файл **`.env`** в корневом каталоге проекта и укажите ваши параметры конфигурации:

```env
PORT=3000
DB_URI=mongodb://localhost:27017
PASSWORD_SALT=замените_на_ваш_секретный_длинный_ключ_для_соли
NODE_ENV=development
```

⚠️ **Важно:** Никогда не отправляйте файл `.env` в публичный репозиторий GitHub! Добавьте его в `.gitignore`.

### 4. Запуск приложения

**Режим разработки (с автоматическим перезапуском при изменении кода через nodemon):**

```bash
npm run dev
```

**Режим продакшена:**

```bash
npm start
```

После этого откройте в браузере страницу: http://localhost:3000

## 🔒 Безопасность и архитектурные решения

1. **HMAC авторизация:** Защита от радужных таблиц и брутфорса паролей за счет подмешивания секретного ключа `PASSWORD_SALT` к криптографическому алгоритму `SHA-256` во время хэширования.
2. **Изоляция данных:** Поиск, чтение и остановка таймеров происходят строго с валидацией принадлежности записи текущему авторизованному `userId`. Межсайтовый перехват или манипуляция чужими ID таймеров исключены.
3. **Безопасность сессий:** Сессионные куки настроены с флагом `httpOnly`, предотвращающим кражу токенов сессий через XSS-атаки на клиенте.
4. **Защита пула соединений от перегрузки:** Вместо классического `setInterval` на бэкенде отправка тиков активных таймеров реализована через рекурсивный `setTimeout`. Следующий шаг планируется в памяти только тогда, когда база данных ответила на предыдущий запрос, что гарантирует стабильность работы пула из 10 соединений (`poolSize: 10`).
