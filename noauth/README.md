# Timers NoAuth ⏱️

Простое и быстрое веб-приложение для отслеживания времени (тайм-трекер). Позволяет создавать именованные таймеры, наблюдать за их ходом в реальном времени и сохранять историю завершенных сессий в базу данных.

Проект построен на базе чистого **Vanilla JS (SPA)** без использования тяжелых фронтенд-фреймворков и интегрирован с экосистемой **Node.js** и **MongoDB**.

---

## 🛠️ Технологический стек

- **Backend:** Node.js, Express (REST API)
- **Database:** MongoDB (официальный нативный драйвер `mongodb`)
- **Frontend:** Vanilla JavaScript (ES6+), UIkit 3 (CSS/JS компоненты и иконки)
- **Инструменты разработки:** ESLint, Prettier, Husky, Lint-staged, Nodemon, Cross-env

---

## 🚀 Особенности реализации

1. **Реактивный интерфейс на чистом JS:** Списки активных и старых таймеров генерируются динамически. Используется эффективное делегирование событий для управления кнопками остановки.
2. **Оптимальная нагрузка на сеть:** Текущий прогресс активных таймеров пересчитывается каждую секунду локально на стороне клиента. База данных и API не спамятся постоянными запросами.
3. **Безопасность данных:** Реализована строгая валидация входящих данных на бэкенде, проверка формата `ObjectId` для предотвращения рантайм-сбоев СУБД, а также автоматическое форматирование кода перед каждым коммитом с помощью Git-хуков (Husky).

## ⚙️ Инструкция по установке и запуску

### 1. Требования

Убедитесь, что у вас установлены:

- **Node.js** версии `>= 12.0.0`
- Запущенный инстанс **MongoDB** (локальный или в облаке MongoDB Atlas)

### 2. Клонирование и установка зависимостей

```bash
git clone <url-вашего-репозитория>
cd timers-noauth
npm install
```

### 3. Настройка переменных окружения

Создайте в корневой директории проекта файл **`.env`** и укажите в нём параметры подключения:

```env
PORT=3000
DB_URI=mongodb://localhost:27017
```

_(Замените `mongodb://localhost:27017` на вашу реальную строку подключения, если используете авторизацию или удаленный сервер)._

### 4. Запуск приложения

- **Режим разработки (с автоматическим перезапуском сервера при изменении кода):**
  ```bash
  npm run dev
  ```
- **Продакшн-режим:**
  ```bash
  npm start
  ```

После запуска приложение будет доступно по адресу: **`http://localhost:3000`**

## 📡 Спецификация REST API

| Метод    | Эндпоинт               | Описание                                                                                                                |
| :------- | :--------------------- | :---------------------------------------------------------------------------------------------------------------------- |
| **GET**  | `/api/timers`          | Возвращает массив всех таймеров. Поддерживает фильтрацию через Query-параметры: `?isActive=true` или `?isActive=false`. |
| **POST** | `/api/timers`          | Создает новый активный таймер. Тело запроса: `{"description": "Название задачи"}`.                                      |
| **POST** | `/api/timers/:id/stop` | Останавливает запущенный таймер по его `id`, фиксирует время окончания и высчитывает итоговую длительность.             |

Клиентский код написан с использованием фреймворка [Vue](https://vuejs.org/) и библиотеки [UIkit](https://getuikit.com/).

Для выполнения задания знать ни то, ни другое не нужно, однако нужно изучить шаблон index.njk на предмет того, какие данные ожидаются от сервера.

Для зачёта выполненного задания достаточно реализовать те методы, которыми пользуется клиентский код.

Важный момент: для того чтобы избежать конфликта между синтаксисом Vue и Nunjucks последние настроены так, что для серверных шаблонов вместо фигурных скобок используются квадратные:

```js
  tags: {
    blockStart: "[%",
    blockEnd: "%]",
    variableStart: "[[",
    variableEnd: "]]",
    commentStart: "[#",
    commentEnd: "#]",
  },
```
